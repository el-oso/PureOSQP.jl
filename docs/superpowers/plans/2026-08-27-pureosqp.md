# PureOSQP.jl Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pure-Julia, stdlib-only OSQP solver for `min ½xᵀPx + qᵀx s.t. l ≤ Ax ≤ u` that accepts any `AbstractMatrix` and never touches sparse-matrix machinery.

**Architecture:** ADMM operator splitting, transcribed from the Apache-2.0 OSQP reference. The inner KKT solve is eliminated to a symmetric positive definite n×n system factored with `cholesky!`, with a full-KKT `bunchkaufman!` fallback when that fails. Ruiz equilibration is stored as factors and applied lazily so the caller's `P` and `A` are never copied or mutated for the per-iteration products.

**Tech Stack:** Julia ≥ 1.10, `LinearAlgebra` only. Tests use `Test` + `ReTestItems` + `OSQP` (oracle) in `test/Project.toml`.

**Spec:** `docs/superpowers/specs/2026-08-27-pureosqp-design.md`

## Global Constraints

- **Dependencies:** `LinearAlgebra` only in `[deps]`. `Test`, `ReTestItems`, `OSQP`, `SparseArrays` go in `test/Project.toml` **only**. Add every dependency with `ion add` or `Pkg.add` — never hand-write a UUID, never edit `Manifest.toml`.
- **License:** Apache-2.0 (matches upstream OSQP).
- **Genericity:** every kernel is generic over `T<:AbstractFloat`; all numeric constants are `convert`ed to `T`. `P` and `A` are `AbstractMatrix` and are never mutated.
- **Struct fields are concrete;** workspace structs are parametric in their matrix types. `isconcretetype(fieldtype(T, :f))` must hold for every field.
- **Idioms:** `iszero(x)`, `isnothing(x)`, `eachindex(a)`, `zero(T)`/`one(T)` for element-typed values.
- **No `@inbounds`** unless a benchmark in the same commit shows the check costs something.
- **Fail fast:** invalid input errors at `setup`; a non-converged result is never returned as success.
- **Oracle:** `OSQP.jl` 0.8.1 / libosqp 0.6.2. Configure it with `adaptive_rho_interval = 50` in every comparison so both solvers are deterministic.
- **Before every commit:** `runic -i .`.

`test/referee.jl` — computes the KKT residuals of a candidate `(x, y)` from the caller's
original data only. No solver internals may appear in this file.

```julia
# Unscaled KKT residuals of (x, y) for  min ½xᵀPx + qᵀx  s.t.  l ≤ Ax ≤ u.
# Computed from the original problem data alone, so it cannot inherit a scaling bug
# from the solver.
function kkt_residuals(P, q, A, l, u, x, y)
    Ax = A * x
    z = clamp.(Ax, l, u)
    r_prim = isempty(Ax) ? zero(eltype(x)) : maximum(abs, Ax .- z)
    r_dual = maximum(abs, P * x .+ q .+ A' * y)
    # Complementarity: y must lie in the normal cone of [l,u] at z.
    r_comp = zero(eltype(x))
    for i in eachindex(y)
        yi, zi = y[i], z[i]
        viol = if yi > 0
            abs(zi - u[i])            # active at the upper bound
        elseif yi < 0
            abs(zi - l[i])            # active at the lower bound
        else
            zero(yi)
        end
        r_comp = max(r_comp, isfinite(viol) ? viol : zero(viol))
    end
    return (r_prim, r_dual, r_comp)
end
```

- [ ] **Step 3: Implement `src/scaling.jl`**

Transcribed from `scaling.c`. The column and row norms of the *currently scaled* matrices
are computed from the original entries and the running factors, so nothing is materialized:

```julia
@inline limit_scaling(v::T) where {T} = v < MIN_SCALING(T) ? one(T) : min(v, MAX_SCALING(T))

# Column ∞-norms of the scaled blocks, without forming them:
#   colnorm(EAD)_j = D_j max_i E_i|A_ij|,  colnorm(cDPD)_j = c D_j max_i D_i|P_ij|
#   rownorm(EAD)_i = E_i max_j D_j|A_ij|
function scale!(ws::Workspace{T}) where {T}
    n, m = length(ws.D), length(ws.E)
    fill!(ws.D, one(T)); fill!(ws.E, one(T)); ws.c[] = one(T)
    copyto!(ws.q, ws.q0); copyto!(ws.l, ws.l0); copyto!(ws.u, ws.u0)
    d = Vector{T}(undef, n); e = Vector{T}(undef, m)
    for _ in 1:ws.settings.scaling
        for j in 1:n
            pj = zero(T)
            for i in 1:n
                pj = max(pj, ws.D[i] * abs(T(ws.P[i, j])))
            end
            aj = zero(T)
            for i in 1:m
                aj = max(aj, ws.E[i] * abs(T(ws.A[i, j])))
            end
            d[j] = limit_scaling(max(ws.c[] * ws.D[j] * pj, ws.D[j] * aj))
        end
        for i in 1:m
            ai = zero(T)
            for j in 1:n
                ai = max(ai, ws.D[j] * abs(T(ws.A[i, j])))
            end
            e[i] = limit_scaling(ws.E[i] * ai)
        end
        d .= inv.(sqrt.(d)); e .= inv.(sqrt.(e))
        ws.D .*= d; ws.E .*= e; ws.q .*= d
        # cost normalization
        acc = zero(T)
        for j in 1:n
            pj = zero(T)
            for i in 1:n
                pj = max(pj, ws.D[i] * abs(T(ws.P[i, j])))
            end
            acc += ws.c[] * ws.D[j] * pj
        end
        ct = max(acc / n, limit_scaling(maximum(abs, ws.q; init = zero(T))))
        ct = inv(limit_scaling(ct))
        ws.q .*= ct
        ws.c[] *= ct
    end
    ws.l .= ws.E .* ws.l0
    ws.u .= ws.E .* ws.u0
    return ws
end
```

Note `ws.q0`, `ws.l0`, `ws.u0` hold the caller's originals; `ws.q`, `ws.l`, `ws.u` hold
the scaled copies. Vectors may be copied — only `P` and `A` are left alone.

Lazy products, with a scratch vector `ws.tmp_n` / `ws.tmp_m` to avoid allocating:

```julia
function mul_A!(out::AbstractVector{T}, ws::Workspace{T}, x::AbstractVector{T}) where {T}
    ws.tmp_n .= ws.D .* x
    mul!(out, ws.A, ws.tmp_n)
    out .*= ws.E
    return out
end

function mul_At!(out::AbstractVector{T}, ws::Workspace{T}, y::AbstractVector{T}) where {T}
    ws.tmp_m .= ws.E .* y
    mul!(out, ws.A', ws.tmp_m)
    out .*= ws.D
    return out
end

function mul_P!(out::AbstractVector{T}, ws::Workspace{T}, x::AbstractVector{T}) where {T}
    ws.tmp_n .= ws.D .* x
    mul!(out, ws.P, ws.tmp_n)
    out .*= ws.D
    out .*= ws.c[]
    return out
end
```

- [ ] **Step 3: Implement `src/linsys.jl`**

```julia
# Reduced system:  (P̃ + σI + Ãᵀ diag(ρ) Ã) x̃ = rhs_x + Ãᵀ(ρ ⊙ rhs_z),  z̃ = Ã x̃
# The scaled Ã is materialized once per factorization into ws.W with sqrt(ρ) folded in,
# so the reduced matrix is a single syrk.  Falls back to a Bunch-Kaufman factorization of
# the full quasi-definite KKT matrix when the Cholesky is not positive definite, which is
# what happens once cond(Ã) exceeds roughly 1e9.
function refactor!(ws::Workspace{T}) where {T}
    n, m = length(ws.D), length(ws.E)
    for j in 1:n, i in 1:m
        ws.W[i, j] = sqrt(ws.rho_vec[i]) * ws.E[i] * T(ws.A[i, j]) * ws.D[j]
    end
    mul!(ws.R, ws.W', ws.W)
    for j in 1:n, i in 1:n
        ws.R[i, j] += ws.c[] * ws.D[i] * T(ws.P[i, j]) * ws.D[j]
    end
    for i in 1:n
        ws.R[i, i] += ws.settings.sigma
    end
    F = cholesky!(Symmetric(ws.R); check = false)
    if issuccess(F)
        ws.chol[] = F
        ws.backend[] = :cholesky
    else
        build_full_kkt!(ws)
        ws.bk[] = bunchkaufman!(Symmetric(ws.K, :L); check = true)
        ws.backend[] = :bunchkaufman
    end
    return ws
end
```

`build_full_kkt!` fills the `(n+m)×(n+m)` buffer `ws.K` with the scaled
`[P̃+σI  Ãᵀ; Ã  -diag(ρ⁻¹)]`. `solve_kkt!` branches on `ws.backend[]`: the Cholesky path
forms `rhs_x + Ãᵀ(ρ ⊙ rhs_z)` into `ws.xtilde`, `ldiv!`s, then sets `ws.ztilde = Ã x̃`;
the Bunch-Kaufman path concatenates the right-hand sides into `ws.kkt_rhs`, `ldiv!`s, and
splits the result, recovering `z̃ = rhs_z + ρ⁻¹ ⊙ (ν − y)`.

`ws.backend`, `ws.chol`, `ws.bk` are `Ref`s of concrete factorization types
(`Base.RefValue{Cholesky{T, Matrix{T}}}` etc.) so the workspace stays concretely typed;
`ws.backend[]` is a `Symbol` read once per solve, not in the inner loop.

```julia
function admm_step!(ws::Workspace{T}) where {T}
    α = ws.settings.alpha
    ws.x, ws.x_prev = ws.x_prev, ws.x
    ws.z, ws.z_prev = ws.z_prev, ws.z
    # rhs = (σ x_prev − q,  z_prev − ρ⁻¹ ⊙ y)
    @. ws.rhs_x = ws.settings.sigma * ws.x_prev - ws.q
    @. ws.rhs_z = ws.z_prev - ws.rho_inv_vec * ws.y
    solve_kkt!(ws, ws.rhs_x, ws.rhs_z)
    @. ws.x = α * ws.xtilde + (one(T) - α) * ws.x_prev
    @. ws.delta_x = ws.x - ws.x_prev
    @. ws.z = α * ws.ztilde + (one(T) - α) * ws.z_prev + ws.rho_inv_vec * ws.y
    @. ws.z = clamp(ws.z, ws.l, ws.u)
    @. ws.delta_y = ws.rho_vec * (α * ws.ztilde + (one(T) - α) * ws.z_prev - ws.z)
    @. ws.y += ws.delta_y
    return ws
end
```

`src/termination.jl` implements, from `auxil.c`:

- `compute_prim_res` = `‖Ãx − z‖_∞`, unscaled as `‖E⁻¹ ⊙ (Ãx − z)‖_∞`;
- `compute_dual_res` = `‖P̃x + q̃ + Ãᵀy‖_∞`, unscaled as `c⁻¹‖D⁻¹ ⊙ (·)‖_∞`;
- `eps_prim = eps_abs + eps_rel · max(‖E⁻¹z‖, ‖E⁻¹Ãx‖)`;
- `eps_dual = eps_abs + eps_rel · c⁻¹ max(‖D⁻¹q̃‖, ‖D⁻¹Ãᵀy‖, ‖D⁻¹P̃x‖)`;
- `NON_CONVEX` when either residual exceeds `INFTY(T)`.

`solve!` runs the loop, evaluates residuals every `check_termination` iterations (and on
iteration 1), and unscales the returned `x` by `D` and `y` by `c⁻¹E` before building the
`Solution`.
